| train: 354к запросов, но 74к уникальных текстов, 2.45 слова; бенчмарк: 3.2 слова, хвост | valid/test строятся «как бенчмарк»: 1 запрос на текст, 41% знакомых текстов |
| до 278 выборов на запрос (99.9% ≤ 18) | чистка обучения: `MAX_POS_PER_QUERY=20`, ≤3 запроса на один текст |

## Офлайн-замеры на реальных данных (без обучения моделей, только BM25-каналы)

1600 отложенных «бенчмарк-подобных» запросов, корпус = train_items + benchmark_items (516к):

| метод | valid | test |
|---|---|---|
| v1: BM25 top-300 по стране + 40·loc | 0.453 | 0.426 |
| BM25 только гео-зона, top-50 | 0.730 | 0.694 |
| **простой скор без моделей** (`generate_quick_geo_answer.py`) | **0.769** | **0.731** |
| потолок пула (все BM25-каналы, ~350 канд.) | 0.880 | 0.850 |
| recall@200 простого скора | 0.837 | 0.805 |

Про идею «в top-200/1000 уже всё есть»: в top-200 ~80–84%, в пуле ~350 — 85–88%, и это только
BM25. Dense-каналы добавят. Остальные 12–15% не находит ни один лексический канал — это
работа эмбеддингов.

## Порядок

```
uv run python generate_quick_geo_answer.py   # ~5-10 мин, без моделей -> answer_geo_simple.csv
uv run python 04_train_reranker_v2.py         # пул + N моделей + ансамбль + подбор эвристик
uv run python 05_analyze_validation.py        # разбор ранжирования на valid/test, misses.csv

```
Для CatBoost: `uv add catboost`. На GPU: `CATBOOST_TASK_TYPE="GPU"` в config_v2. Без catboost
модель просто пропускается.

## План попыток (осталось 5)

1. **`answer_geo_simple.csv`** — уже посчитан и лежит в папке. Проверяет главную гипотезу
   (гео-пул) без всяких моделей. Офлайн: +0.30 к v1 на тех же запросах.
2. 04 + final с эмбеддингами (текущие кэши 02) и ансамблем.
3. Перегнать 02 с исправленным текстом (01 и 02 кодировали объявления по-разному), затем 04 → final.
4. 01b (хард-негативы) или другой бэкбон → 02 → 04 → final; и/или 06 (cross-encoder),
   если на valid лучший w > 0.
5. Резерв.

Отправлять имеет смысл, когда на test прирост больше ~0.005: test = 800–1500 запросов,
шум ±0.01.

## Что добавлено по последнему списку

* **CatBoost + N моделей** (`models_v2.py`): `lgb_lambdarank`, `lgb_binary`, `catboost_yetirank`.
  Скор ансамбля — взвешенный RRF по рангам (шкалы моделей не важны), веса подбираются на valid.
* **«Брать разные товары из разных моделей»**: столбцы `rank_model_<имя>` участвуют в квотах
  «гарантированно взять top-q от модели X» вместе с квотами каналов. Всё подбирается на valid.
* **Эвристики top-50** (`postprocess_v2.py`, подбор координатным спуском на valid, принимается
  только прирост > 0.002 и только если test не хуже):
  * жёсткие фильтры (в конец списка, не выкидываются): `filter_ok` (Вид/Тип услуги),
    `mc_plausible` (микрокатегория почти не встречается для слов запроса), `in_geo`, `rating_ok`;
  * **разнообразие** «домешать 1–2 из другой группы»: последние D мест отдаются лучшим
    объявлениям из другой микрокатегории / вне гео-зоны / другой отзывной группы (0 / 1–10 / 10+).
  На простом скоре офлайн ни одна жёсткая эвристика не дала прироста (фильтры уже учтены в скоре).
  Для обученного ансамбля они подберутся автоматически.
* **Чистка обучения**: запросы с > 20 выборами, пустые запросы, ≤ 3 запроса на текст,
  тексты valid/test исключены из train ре-ранкера.

## Память

Корпус обучения = 516к объявлений. В контейнере с 8 ГБ всё проходит после того, как тексты
освобождаются сразу после построения BM25 (пиково ~5 ГБ). Если на ноутбуке тесно:
`BATCH_QUERIES=32`, `NEG_KEEP=0.5` в 04, `AUGMENT_TRAIN_CORPUS_WITH_BENCH=False`.

## Про LLM (из прошлого ответа, коротко)

Ре-ранкер — Qwen3-Reranker-0.6B / bge-reranker-v2-m3 (06). Эмбеддинги — Qwen3-Embedding-0.6B /
USER-bge-m3 / FRIDA вместо e5-base. Генеративные 7–8B в 4 битах в 6 ГБ влезают, но сжатие
500к объявлений — это дни, а листовой ре-ранкинг генерацией — 10+ часов с выдуманными id.

Open-source, которые используются: scikit-learn, scipy, LightGBM, CatBoost, nltk (Snowball),
sentence-transformers, FAISS, multilingual-e5-base; опционально Qwen3-Reranker / bge-reranker.
