# Avito: кандидатогенерация для поиска услуг

Задача: для каждого из 2452 запросов `benchmark_queries` вернуть до 50 объявлений из 189 212
объявлений `benchmark_items`. Метрика Recall@50.

**Итог на платформе: Recall@50 = 0.9096.**

| отправка | что изменилось | офлайн test | платформа |
|---|---|---|---|
| v1 | BM25 + e5 с обученной головой + LightGBM | — | 0.5520 |
| v2 | гео-зона по истории, каналы кандидатов, новые признаки, 3 модели + ансамбль | — | 0.8872 |
| v2.1 | головы переобучены с отложенными 10% запросов, больше данных для ре-ранкера | — | 0.8957 |
| v2.2 | 30к запросов для ре-ранкера, дообучение на train+valid+test | 0.8632 | 0.8976 |
| **v2.3** | **второй эмбеддер (USER-bge-m3) как отдельные каналы и признаки** | **0.8783** | **0.9096** |

Этот репозиторий воспроизводит последнюю строку.

## Воспроизведение

Окружение: Python 3.11, `uv sync` (есть `pyproject.toml` и `uv.lock`) или `pip install -r requirements.txt`.
Для пересчёта эмбеддингов и обучения нужен GPU (проверено на RTX 3060 Laptop 6 ГБ, 16 ГБ RAM).
Файлы задачи положить в `data/`:

```

data/benchmark_queries.parquet  data/benchmark_items.parquet
```

На Windows в Git Bash перед запуском: `export PYTHONIOENCODING=utf-8`.

В репозитории лежат итоговые модели ранжирования (`artifacts/work/models_refit`).
Обученные головы энкодеров и эмбеддинги бенчмарка - на [Яндекс Диске](https://disk.yandex.ru/d/TnIhfav-C2qJqw).

## Подход

```
запрос ──┬─ BM25 (полный текст)      ┐
         ├─ e5 + голова  (косинус)   ├─ 9 каналов: top-k по всей стране / в гео-зоне /
         └─ bge-m3 + голова          ┘   в гео-зоне с учётом фильтров
                                         │
                            пул ~750 кандидатов на запрос (потолок recall 0.957)
                                         │
                            50 признаков на пару (запрос, объявление)
                                         │
             LightGBM lambdarank + LightGBM binary + CatBoost YetiRank
                                         │
                   ансамбль: взвешенная сумма 1 / (60 + ранг модели)
                                         │
                                       top-50
```

## Данные и признаки

Что видно в данных (`00_diagnostics.py`) и что из этого следует:

| наблюдение | решение |
|---|---|
| 82% выборов из локации поиска, остальные в соседние города. У 17% запросов бенчмарка в локации поиска вообще нет объявлений (это регионы: 107620, 107621, 621540) | гео-зона запроса = локации, куда по истории train уходит ≥ 0.5% выборов из этой локации поиска, плюс сама локация. Каналы `*_geo`, признак `geo_p` = P(локация объявления \| локация поиска) |
| пара "Вид услуги X" из фильтра поиска есть в параметрах выбранного объявления в 98% случаев, "Тип услуги Y" в 95.5% | каналы `*_geo_filt`, признак `filter_ok` |
| `search_category` почти всегда 114 | вместо неё P(микрокатегория \| слова запроса) по истории: `tok_mc_share`, `tok_mc_is_top` |
| корпус бенчмарка есть в train_items только на 9.6% | признаки конкретного объявления (популярность, "его выбирали по такому же запросу") не используются: на бенчмарке они почти всегда пустые |
| фильтр рейтинга: 0.2% запросов train, 0 в бенчмарке | отдельной обработки нет |
| до 278 выборов на запрос; 354к запросов, но 74к уникальных текстов | из обучения ре-ранкера убраны запросы с >20 выборами, не больше 3 запросов на один текст |
| в бенчмарке запросы длиннее (3.2 слова против 2.45) и 59% текстов новые | valid/test собираются как бенчмарк, см. ниже |

Признаки пары (все 50 в `pool.py`):

- **ранги в каналах** (`rank_bm25_geo`, `rank_dense_geo`, `rank_dense2_geo`, ...) и число каналов, нашедших объявление;
- **текст**: BM25 по полному тексту и по заголовку, BM25 относительно лучшего в запросе и в гео-зоне, доля слов запроса в тексте и в заголовке, совпадение фильтров;
- **эмбеддинги**: косинус каждого энкодера, отставание от лучшего косинуса в запросе и в гео-зоне, средний косинус двух энкодеров;
- **гео**: та же локация, в гео-зоне, P(локация объявления \| локация поиска), расстояние до центра локации поиска, размер локаций;
- **объявление**: рейтинг, число отзывов, цена, длина заголовка и описания, скрыт ли телефон;
- **история**: P(микрокатегория \| слова запроса), доля выборов в микрокатегории по такому же тексту;
- **запрос**: число слов, есть ли фильтр, пустая ли категория.

Самые важные по gain: `rank_dense_geo`, `rank_dense2_geo`, `n_channels`, `dist_km_log`,
`cos2_minus_max_geo`, `cos_minus_max_geo`, `item_loc_size`, `geo_p`.

## Модели

**Эмбеддинги** (`01_train_head.ipynb`, `02_encode.py`). Бэкбоны `intfloat/multilingual-e5-base` и
`deepvk/USER-bge-m3` заморожены. Поверх них обучается голова из двух GeGLU-блоков с residual
(`custom_head.py`), InfoNCE с in-batch негативами на парах (запрос, выбранное объявление).
Полный файнтюн на 6 ГБ VRAM не помещался; с замороженным бэкбоном его эмбеддинги считаются один раз.
По отдельности энкодеры дают одинаковое качество (ансамбль 0.8632 и 0.8613 на test), но ошибаются
на разных объявлениях: вместе потолок пула вырос с 0.947 до 0.957, ансамбль с 0.863 до 0.878.

**BM25** (`bm25.py`): своя реализация на разреженных матрицах, стемминг Snowball.
Заголовок повторяется 5 раз (вес поля), параметры и описание обрезаны: дальше обычно прайс.

**Ранжирование** (`rankers.py`): LightGBM lambdarank, LightGBM binary, CatBoostRanker YetiRank.
Ансамбль по рангам: `sum w_m / (60 + rank_m)`, веса перебором по сетке на valid
(итог: lambdarank 1, binary 2, CatBoost 0.5).

**Эвристики top-50** (`postprocess.py`): квоты каналов, жёсткие фильтры, "домешать объявления
другой микрокатегории / вне гео-зоны / другой группы по отзывам". Подбирались на valid с порогом
+0.002; ни одна его не прошла, в итоговом ответе не используются.

**Дообучение** (`04_refit.py`): после проверки на test те же модели с тем же числом итераций (×1.1)
переобучаются на train+valid+test ре-ранкера.

## Как проверялось качество

1. **Без утечки через эмбеддинги.** Головы обучаются на 90% запросов train, 10% отложены.
   Ре-ранкер учится и проверяется только на отложенных: для запросов, которые голова видела,
   косинус у правильных объявлений завышен, и модель слишком бы ему доверяла.
2. **История** (переходы локаций, микрокатегории) при обучении строится только по тем 90%,
   на бенчмарке - по всему train.
3. **valid и test "как бенчмарк"**: по одному запросу на текст и та же доля знакомых текстов (41%).
   Случайная выборка из train - это частые короткие запросы, на ней метрика завышена.
4. **Корпус при обучении** = train_items + объявления бенчмарка без разметки (516к). В train_items
   только объявления, которые кто-то выбрал, без дистракторов задача слишком лёгкая.
5. valid (1074 запроса) - early stopping, веса ансамбля, эвристики. test (1074) - одна итоговая
   цифра. Одни и те же valid/test во всех экспериментах. Отправляли, только когда прирост
   на test был больше 0.005 (шум на 1000 запросах около ±0.01).
6. Перед отправкой 05 печатает средние признаков на train-пуле и на бенчмарке: сдвиг для всех
   признаков объясним (запросы длиннее и реже). Проверка формата ответа.

Разница между экспериментами на test и на платформе совпадала: +0.015 и +0.012 для последнего шага.

## Какие ошибки нашлись и что с ними сделано

**Ошибки модели** (`06_analyze_errors.py`, recall@50 на test по сегментам):

| сегмент | recall | что сделано |
|---|---|---|
| в локации поиска нет объявлений (15% запросов) | 0.786 против 0.895 | гео-зона строится по истории переходов: регион → города, куда из него уходят выборы. В v1 буст «та же локация» для таких запросов всегда был 0. Разрыв с остальными запросами остался |
| запрос без фильтров | 0.857 против 0.894 | каналы `*_geo_filt` работают только с фильтром; компенсируют dense-каналы |
| 4 слова в запросе | 0.855 | длинные редкие запросы; второй эмбеддер поднял все сегменты, этот остаётся самым слабым |
| выбор не из локации поиска (18% выборов) | — | каналы `*_global`, гео-зона по истории, признак расстояния |

Потолок пула 0.957, а в top-50 попадает 0.878: основная потеря - в ранжировании внутри пула,
а не в поиске кандидатов.

**Ошибки в данных и пайплайне**:

- выбросы: запросы с сотнями выборов, пустые запросы, повторяющиеся тексты - удалены из обучения ре-ранкера;
- `item_price` с мусором (-1, 999999999999) - обрезка до [0, 10^6];
- фраза "Рейтинг пользователя 4 звезды и выше" в фильтре искалась BM25 как обычные слова - убрана из текста запроса;
- параметр "Тип услуги автосервиса" в среднем на 836-м символе параметров, обрезка его теряла (`filter_ok` был верен лишь для 85% позитивов) - проверка по вырезанным кускам после ключей (96%);
- голова обучалась на тексте с одной обрезкой, а применялась к другой - один источник текста для 01 и 02;
- `bm25_rel_geo` делился на ~0, если в гео-зоне нет совпадений - теперь пропуск;
- CatBoost на GPU не принимает группы длиннее 1023 строк - в каждой группе оставляются все позитивы и лучшие по рангу каналов.

## Что пробовали и не вошло

- эвристики top-50 (квоты, жёсткие фильтры, разнообразие) - прирост на valid меньше 0.002;
- более широкие каналы (больше кандидатов) - потолок пула растёт, recall@50 нет;
- USER-bge-m3 вместо e5 - то же качество (0.8613 против 0.8632), полезен только вместе с e5;
- признаки популярности конкретных объявлений - см. раздел про данные;
- генеративная LLM для сжатия описаний или реранкинга: на 6 ГБ VRAM обработка 500к объявлений заняла бы дни.

Используемые open-source компоненты: scikit-learn, scipy, numpy, pandas, nltk (Snowball),
LightGBM, CatBoost, PyTorch, sentence-transformers, модели intfloat/multilingual-e5-base
и deepvk/USER-bge-m3.
